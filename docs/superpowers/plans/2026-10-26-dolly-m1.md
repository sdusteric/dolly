# Dolly M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Dolly M1: record a window, area or display with a pointer and click log, turn clicks into zooms, edit them in the Spike marks editor, and export a 16:9 H.264 mp4.

**Architecture:** A SwiftPM app shaped like Snap and Reel. `DollyCore` holds every rule as pure, tested values (takes, pointer log, clicks, zoom rules, camera path, edits, export plan). `DollyRender` turns a take plus a camera path into frames with Core Image and serves both the preview player and the exporter. `DollySystem` is the only place that touches ScreenCaptureKit, Carbon and input polling. `DollyUI` draws direction A in SwiftUI inside AppKit windows.

**Tech Stack:** Swift 6.4 tools, Swift 6 language mode, macOS 27, SwiftUI and AppKit, ScreenCaptureKit, AVFoundation (`AVAssetWriter`, `AVAssetReader`, `AVVideoCompositing`), Core Image on Metal, Vision, Sparkle 2.10.0, Swift Testing, swiftlint.

**Spec:** `docs/superpowers/specs/2026-10-26-dolly-design.md` (approved 2026-10-26: direction A and the spec). Product truth: `PRODUCT.md`. Visual target: `docs/mockup/directions/a-light.png`, `a-dark.png`, `a-spike-marks.html`.

## Review Focus

1. **A crash or quit mid-recording.** The owner expects the take to survive. `take.mov` is written with `movieFragmentInterval` 2 s and `pointer.bin` is appended and flushed every second, so a killed process leaves a playable movie and a readable log up to the last fragment. Test in Task 11 (`killedWriterLeavesPlayableFragment`) and Task 3 (`truncatedLastRecordIsDropped`).
2. **Damaged or missing take files.** A take folder with no `take.json`, bad JSON, or no `take.mov` lists as "Can't open this take" and never crashes the sidebar. Test in Task 2 (`listSkipsNothingAndMarksBroken`).
3. **Clicks at the very edge and zooms near the start or end.** A click in a corner, a click at 0.1 s, and one 0.2 s before the end all give zooms whose camera stays inside the recording and whose times stay inside the trim. Tests in Task 5 (`leadInClampedAtStart`) and Task 6 (`cornerClickClampsView`).
4. **Take names that are bad file names and repeated exports.** "Demo: v2/final" exports as `Demo- v2-final 16x9.mp4`, and a second export of the same take becomes `... 16x9 2.mp4`, never overwriting. Test in Task 9 (`sanitizesAndNumbersFileNames`).
5. **Edits that shrink a zoom to nothing.** Dragging a strip's end past its start, or trimming over a whole zoom, keeps a zoom at least `moveIn + moveOut + 0.2` s long or removes it with undo available. Test in Task 8 (`resizeKeepsMinimumLength`, `trimOverWholeZoomRemovesIt`).

### Task 6: Shape layout and camera path

**Files:**
- Create: `Sources/DollyCore/Zoom/{ShapeLayout,CameraPath,Easing}.swift`, `Sources/DollyCore/Export/ShapePreset.swift`
- Test: `Tests/DollyCoreTests/CameraPathTests.swift`, `ShapeLayoutTests.swift`

**Interfaces:**
- Consumes: `Zoom`, `Look.padding`, smoothed pointer from Task 7 (`PointerPath.position(at:)`) for follow zooms.
- Produces:
  - `enum ShapePreset: String, Codable, CaseIterable, Sendable { case wide16x9, square1x1, portrait4x5, tall9x16 }` with `pixelSize` (1920x1080, 1080x1080, 1080x1350, 1080x1920), `label` ("16:9"...), `fileSuffix` ("16x9"...). M1 exports only `.wide16x9`; the others exist so Task 6 tests the general math.
  - `struct ShapeLayout: Sendable { init(shape: ShapePreset, recordingSize: CGSize, padding: Double); let canvas: CGSize; let recordingRect: CGRect /* canvas px */; func canvasPoint(_ recording: CGPoint) -> CGPoint; func viewRect(_ camera: CameraState) -> CGRect }`. Padding in px = `padding * min(canvas.width, canvas.height) / 1080`. The recording is fitted (aspect kept) inside the canvas minus padding, centered.
  - `struct CameraState: Hashable, Sendable { depth: Double; center: CGPoint /* canvas px */ }`
  - `struct CameraPath: Sendable { init(zooms: [Zoom], layout: ShapeLayout, pointer: PointerPath?, duration: Double); func camera(at t: Double) -> CameraState }`
  - `enum Easing { static func inOut(_ u: Double) -> Double }` = cubic bezier (0.45, 0, 0.25, 1).

`viewRect`: size `canvas / depth`, centered on `center`, then per axis: if the view is at least the recording's size on that axis, center on the recording; else clamp inside `recordingRect` (the same rule as `docs/mockup/directions/frame.js`).

Camera algorithm (spec 5.2), the one part the tests do not fully pin:

```
rest = CameraState(depth: 1, center: layout.recordingRect.mid)
held(z, t) = CameraState(depth: z.depth, center: z.mode == .hold ? canvasPoint(z.aim) : followCenter(z, t))
camera(t):
  z = the latest-starting zoom with z.start <= t < z.end, else return rest
  inEnd = z.start + z.moveIn, outStart = z.end - z.moveOut
  if t < inEnd:   from = camera(z.start - 1e-6)   // whatever was showing, so overlapping zooms blend
                  return lerp(from, held(z, inEnd), Easing.inOut((t - z.start) / z.moveIn))
  if t < outStart: return held(z, t)
  next = the zoom starting in [outStart, z.end), if any: its move-in takes over (handled by "latest-starting")
  return lerp(held(z, outStart), rest, Easing.inOut((t - outStart) / z.moveOut))
followCenter: precomputed at 120 Hz from z.start: target = the pointer in canvas px; the camera center
  moves only when the pointer leaves the middle 60% of the current view, by the amount that puts it
  back on the dead zone's edge, smoothed by a critically damped spring with response 0.4 s.
```
